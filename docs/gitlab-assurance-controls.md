# GitLab audit lifecycle, MFA and key assurance

GLAB-088?101 cover the 14 requested rules. Merge assurance_controls from the [example evidence](examples/gitlab-assurance-control-evidence.json) into the existing gitlab_stig_audit_control_evidence_file. The example approvals, test outcomes, dates, fingerprints and policy OIDs are illustrative; they are not approved production values. The outer observed_at/reference follow the same freshness requirements as the other checks. Missing/stale facts stay Not_Reviewed; verified gaps become Open. All checks have independent V-ID mappings and overrides.

Configure the organization-defined scope keys in gitlab_stig_audit_controls: privilege_modification_operations, privilege_deletion_operations, key_management_scopes, certificate_policy_requirements, log_transfer_sources, log_transfer_real_time_limit_seconds, classified_crypto_paths, audit_information_scopes, mfa_access_matrix, maintenance_paths, organization_trust_stores, approved_trust_anchors and cryptographic_key_stores. management_interfaces, session_termination_methods and privileged_role_operations are reused from existing checks. Empty lists mean unknown scope, except explicitly documented non-applicability below.

Most evidence sections have inventory_complete=true and items keyed by the policy scope list. Each item supplies recent tested_at, test_reference and configuration_reference, plus the rule-specific facts. JSON true/false must be actual booleans. References must support the claims; the role does not itself perform privileged changes, concurrent logons, maintenance connectivity tests, alert delivery, cryptographic approval or MFA/recovery bypass exercises.

## Additional bounded local collection

```yaml
gitlab_stig_public_certificate_paths:
  web: /etc/gitlab/ssl/gitlab.example.mil.crt
gitlab_stig_key_storage_paths:
  secrets: /etc/gitlab/gitlab-secrets.json
```

Public-certificate collection reads up to eight 64-KiB PEM files, inspects the first certificate as the leaf, and exports only its fingerprint, policy OIDs and validity dates. It neither exports certificate contents nor infers a certificate class from issuer names or key sizes. The approving authority's certificate policy/reference must substantiate the class and intended usage. Missing/invalid measurement is inconclusive. The approved OID example in the JSON is deliberately fictitious.

Key storage collection obtains path metadata, resolved path and available getfacl metadata for up to 32 paths. It deliberately never opens or hashes a key/secret file. Effective sudo/group/ACL and backup safeguards remain referenced review facts. Include every relevant file, store, dependency and override in the reviewed inventory; the selected metadata paths alone do not establish completeness. The collector shares the existing bounded command budget, so unavailable tools or exhausted time remain inconclusive. Ansible's discovered/configured Python interpreter is used on RHEL 8; no additional Python package is required for default collection.

Session references must be protected report references or non-secret surrogates, never reusable session cookies/tokens. End-time coverage must include applicable expiry and revocation rather than assuming an explicit logout event covers every ending. Two IP addresses/user agents are not automatically distinct workstations; the referenced test must substantiate workstation identity. A current active-session list is not a historical session-end log.

A real-time transfer limit must reflect a reviewed definition compatible with real-time delivery; setting a permissive numeric limit cannot replace real_time_verified evidence. Verify actual receipt/history at the destination, not only a configured forwarding target. No transfer or alert messages are initiated by the role.

## Explicit non-applicability

For classified_crypto only, an empty classified_crypto_paths list plus inventory_complete=true, classified_information_present=false, scope_reference and no items establishes Not_Applicable. Do not infer this from a banner, CUI marking or absence of a classified-crypto configuration setting.

For maintenance_separation only, an empty maintenance_paths list plus inventory_complete=true, none_present=true, scope_reference and no items establishes Not_Applicable. No other missing scope list in this group automatically becomes Not_Applicable.
